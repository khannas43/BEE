# WP06.1a — Local test-report document intake

**Status:** Implemented locally on branch `wp06.1a-document-intake`; local checks pass (see Evidence). **Not independently reviewed or accepted.** WP06 and WP05 remain open; overall work-package count stays 1/11.

## Scope

- Local SHA-256 content-addressed store under `.local/documents` (git-ignored; `BEE_DOCUMENTS_STORE`, default 5 MiB via `BEE_DOCUMENTS_MAX_BYTES`).
- PostgreSQL metadata: `model_application_document` + immutable `model_application_document_version` (Flyway **V23**).
- Spring: `GET/POST /api/model-applications/{id}/documents`, `GET .../documents/{documentId}/versions/{versionId}/content`.
- Next BFF mirrors under `/api/runtime/...` with multipart forward (no re-encode) and PDF streaming.
- Upload: manufacturer or authorised agency with active filing scope on **own draft** only; brand rechecked at upload time.
- List/content: Spring `SlicePolicy` read scope; cross-org, unknown and malformed IDs → identical `404 not_found`.
- Versions preserve hash, size, media type, original filename, report label, optional tested-on / laboratory name (display only), uploader and time.
- PDF-only for now: magic bytes `%PDF-`. The stored display name is sanitised (path stripped, unsafe characters replaced, always ending `.pdf`, at most 180 characters) and never a reason to reject; the download header carries an ASCII-safe form.
- Truthful label: `pending_local_verification` / verification note — no lab accreditation, malware clearance or BEE approval claim.
- No public downloads; authenticated scoped retrieval only.
- Idempotency: `Idempotency-Key` on upload; body hash over file bytes + metadata (not multipart boundary).
- Consistency: commit the blob by hash first; then, in one transaction (`DocumentRecorder`), lock the application row, re-check it is still a draft, write header and version, and complete the idempotency record. Any failure rolls all of it back; orphan blobs after a DB failure are harmless; missing blob after metadata → `503`.
- UI: contextual **Test reports** card on the existing draft edit form (no new top-level menu).
- Contract artifact **0.5.0**.

## Independent review fixes (`code-review high`, 40f2dd7..1b530cb)

1. Upload after submit: the recorder takes `FOR NO KEY UPDATE` on the application row and re-checks `state = 'draft'` in the same transaction as the insert (DB tests: refusal writes nothing; refusal after a committed submit).
2. Idempotency after commit: metadata and idempotency completion now commit or roll back together; a failure no longer abandons a key for an upload that committed (DB tests: completion in the same transaction; rollback leaves no header or version).
3. Concurrent uploads: the same row lock serialises them into correctly numbered versions under one header (DB test: four concurrent first uploads).
4. Missing multipart part: optional on the controller so the caller is authorised first; the service and a handler answer the contract's 422 (MockMvc and live BFF check).
5. Multipart request limit: `max-request-size` is now 6 MiB (`BEE_DOCUMENTS_MAX_REQUEST_BYTES`), above the 5 MiB file limit (live check: a file of exactly 5 MiB is accepted through Tomcat).
6. BFF body bound: the upload body is read through a bounded stream that stops at 6 MiB, with or without `Content-Length` (`bounded-body.test.mjs`).
7. Filenames: sanitised instead of rejected (unit tests; live check with a Hindi, bracketed name and an ASCII-safe download header).
8. UI idempotency key: bound to file name, size, modified time and label, so a different file or label gets a new key.

Second review round (`1b530cb..307dccf`, no high-severity findings) — fixed:

- Authorisation precedes payload handling: write scope and ownership are checked before any part is validated or the file is read and hashed, so a read-only or other-organisation caller gets 403/404, not 422 (MockMvc cases for both, live cross-organisation check).
- A malformed or truncated multipart body is 422 (`MultipartException` handler; unit test and live check). The global `MissingServletRequestParameterException` mapping was removed.
- `DocumentRepository.recordVersion` and `lockApplicationState` require the recorder's transaction (`Propagation.MANDATORY`; not enforced in tests that construct the repository by hand).
- Sanitiser edge cases: `.pdf` alone, trailing space or dot after truncation, and the zero-width joiner/non-joiner in Indic names.
- The response view is built once. The submit-interleaving test now holds the row lock open while a submit-style update races, and a dead line was removed.

Known limits left as they are: the 6 MiB request limit, the BFF's 6 MiB cap and `BEE_DOCUMENTS_MAX_BYTES` are separate settings (raise all three together); the bounded read holds up to about twice the body size briefly.

Deferred to WP06.2 (review finding 9): `LocalSha256FileStore.commit` accepts an existing blob on size alone, so a corrupted blob is not repaired by re-upload, and orphaned `.tmp` staging files are not swept. Integrity checking, quarantine and cleanup belong with the retention and malware policy.
