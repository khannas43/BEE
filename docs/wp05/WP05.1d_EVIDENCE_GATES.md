# WP05.1d — Submit-time evidence gates

**Status:** Implemented locally on branch `wp06.1a-document-intake`; local checks pass (see Evidence). **Not independently reviewed or accepted.** WP05 and WP05.1 remain open; the work-package count stays 1/11.

**Provisional local defaults, not BEE rules.** The owner accepted the recommended answers of [WP05.1d_DECISIONS.md](WP05.1d_DECISIONS.md) on 3 October 2026. BEE has decided none of them, and the product says so.

## What an application now needs before it can be submitted

| Gate (error code) | Rule | Status when unmet |
| --- | --- | --- |
| `test_report_required` | At least one test report version is stored (WP06.1a) | 422 |
| `declared_efficiency_required` | A declared efficiency figure (ISEER) is set | 422 |
| `test_date_invalid` | A test date is set and is not after today (India date) | 422 |
| `laboratory_not_accredited` | A laboratory is chosen and the accreditation master has an **active** record for it and the category on the test date (suspended, withdrawn, a gap or no record all fail) | 422 |
| `standard_not_available` | The category's `performance_test` standard master has a version in force on the test date | 422 |
| `duplicate_model` | No other application that is not a draft and not rejected holds the same brand and model number (trimmed, case-insensitive) | 409 |

Every gate is evaluated, so the submit preview (`GET .../submit`) lists all six in a fixed order as `evidenceGates` and `ready` is false while any is unmet. Submit refuses on the first unmet gate in the order above. The checks run after the existing ones (scope, ownership, draft state, version, brand, fee rules), so those answers are unchanged.

## What changed

- **Flyway V24:** `laboratory_code`, `tested_on` and `declared_iseer` on `model_application`; four columns that keep the accreditation and standard versions the submit check resolved (written in the submit transaction, not exposed by the API); and a partial unique index on (brand, normalised model number) for applications that are neither draft nor rejected. V23 is untouched.
- **Draft writes:** create and edit accept the three fields as optional. An edit with an absent field keeps the stored value and an explicit null clears it. Malformed values (a laboratory that is not an active laboratory organisation, a future test date, a non-positive or over-precise efficiency) are `422 validation_failed`. Evidence can only change while the application is a draft.
- **Same-model submits queue** on a transaction-scoped advisory lock, so the uniqueness check sees the committed winner; the index is the backstop.
- **`eligible-brands` carries a `laboratories` list** (laboratories with any RAC accreditation record). The date check happens at submit.
- **Contract 0.6.0:** the three optional fields on the model schemas and the create and edit bodies, `laboratories`, `evidenceGates`, six error codes with fixed messages, and the submit 422 and 409 responses for both layers.
- **Form:** a Test evidence card (laboratory chosen from the list, test date, declared efficiency); an unsaved evidence change counts as dirty and blocks the submit review; the confirm card shows the six checks with met or unmet state.
- **Kept out of scope:** documents after a return, who verifies a report and with what outcomes, other required documents, families, the rating, and the fee (BL-012, BL-042).

## Independent review (`7a18a38..7d78d0c`, no high-severity findings) — fixed

- A typo in the efficiency field is reported and never sent as null: an unparseable value used to serialise as null, silently clearing a saved figure on edit. The form now blocks the save with a message (live check: the saved value is unchanged).
- A request number keeps its exact decimal value (`use-big-decimal-for-floats`), so a figure with more than two decimals is refused instead of rounded by a binary double (contract test and live check with `9.9999999999999999`). The contract description now says Spring enforces this on write and the BFF only forwards.
- The accreditation gate also requires the laboratory organisation to be active now, not only when the draft was saved (database test).
- The laboratory list offers only codes the API contract can carry, so one odd organisation code cannot make the whole form response invalid (database test).
- One India date is used for the brand check, the fee rules and the evidence gates, taken before any wait on the model lock, and the advisory-lock wait is bounded at 10 s (a retryable 503 instead of an indefinite wait).
- `useRuntimeRead` forgets a closed detail's read, so reopening the same record shows loading instead of the old copy.
- A real concurrency check: two same-model drafts submitted at the same instant through the BFF give exactly one 200 and one 409 `duplicate_model` (two runs, a different winner each time). With the advisory lock disabled it returns a 503 from the unique index, so the check does fail.

Recorded, not fixed (BL-073 to BL-076): the free-text laboratory and date on a report version are not reconciled with the application's; V24 fails on a database that already holds duplicate live applications; the lock timeout is untested; the kit hook reset has no unit test.

## Limits

- `standard_not_available` is not exercised live: the seeded standard and accreditation both start on 2026-01-01, so the seed cannot make it unmet without also failing accreditation. It is covered by the contract test and the BFF stand-in.
- The efficiency bound (positive, at most 99.99, two decimals) and the absence of a maximum test age are placeholders for BEE answers (decisions 3 and 5).
- Model-number uniqueness folds case and trims spaces only; whether `NC-1` and `NC1` are the same model is a BEE question, and families are deferred.
- Items are tracked as BL-063 to BL-076 in [../BACKLOG.md](../BACKLOG.md).
