# WP05.1b — Model application draft create and edit

Status: **implemented locally; review corrections required, not accepted.** WP05.1 and WP05 remain open; work-package count stays **1/11**. Branch `wp05.1b-model-drafts` from reviewed WP05.1a tip `5e157df`.

Manufacturers and authorised agencies can **create** and **edit draft** model applications through Spring, the Next.js BFF, and the new-model-application form. New rows store filing organisation (`organisation_id`), principal organisation and brand id; seeded rows without a safe brand link keep null brand columns. Submit, fees, rating, approval and history stay denied. None of the 540 matrix proposals is granted.

## API (contract 0.4.0)

| Operation | Route | Notes |
| --- | --- | --- |
| GET eligible brands | Spring `/api/model-applications/eligible-brands`, BFF `/api/runtime/model-applications/eligible-brands` | Scoped list for the form |
| POST create draft | Spring POST `/api/model-applications` | Requires `Idempotency-Key`; stores brand linkage |
| PATCH edit draft | Spring PATCH `/api/model-applications/{id}` | Draft state only; optimistic `version` |

Idempotency store: Flyway **V7** (`idempotency_record`). Replay returns `Idempotency-Replayed: true`. Conflicts: `version_conflict`, `idempotency_key_conflict`, `idempotency_in_progress`.

## Review blockers (1 October 2026)

1. The portal offers only a create form. `NewModelApplication.tsx` has no edit mode or PATCH action, and the model dashboard has no Edit control. The requested end-to-end edit path is therefore API-only.
2. The new form remains under the preview-based route and `ScreenChrome` gates, with sample-data/access wording. A signed-in manufacturer or agency in a fresh profile should reach this Spring-backed form from a runtime menu entry without choosing a preview role, as WP05.1a does for the dashboard.
3. `local:model-drafts` creates persistent model-application rows and changes seeded `LOCAL-MA-0001` from version 0, but its teardown removes only disposable identities and idempotency rows. The script is not baseline-preserving or repeatable. `local:check` still expects exactly four model applications, so running it after the draft test would fail the fixture count. Use disposable applications for write tests, restore or delete all test rows in `finally`, compare before/after, run the test twice, then run the full local check.
4. `ModelApplicationRepository.nextReference()` computes `MAX(reference) + 1`; concurrent creates with different idempotency keys can choose the same reference and one will fail. Add a database-backed allocator in a new V8 migration (do not rewrite applied V7), with a concurrent-create test.
5. The create form generates a new idempotency key for every click, including a retry after an unknown network outcome. Retain the same key for the same payload until its outcome is known; change keys when the payload changes. Test a lost-response retry to prove one draft is created.

The 12/12 focused browser run and other reported checks are useful evidence for the paths they exercised, but they do not close these blockers. WP05.1b, WP05.1 and WP05 remain unaccepted; the work-package count stays 1/11.
