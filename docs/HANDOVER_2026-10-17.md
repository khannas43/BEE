# BEE portal: hand-over note, 17 October 2026

For the team taking over the code. Read this first, then `README.md`, then `docs/demo/DEMO_SCRIPT.md`. Older hand-over notes (`HANDOVER_2026-10-03.md`) are superseded; their paths are obsolete.

## 1. What this is
A local demonstration of a BEE Standards and Labelling portal for a client presentation. It runs only on a laptop (PostgreSQL, Keycloak, a Spring API and a Next.js portal). All data is synthetic. Three things are simulated and labelled so on screen: the Fabric ledger (PostgreSQL tables with a hash chain, no blockchain nodes), the payment gateway, and the five AI helpers (transparent rules and statistics, advisory only).

## 3. What was built for the demonstration (all rehearsed on screen)
Use cases in the presenter script (59 minutes in all):
1. Fee payment by a manufacturer and Finance reconciliation (simulated gateway).
2. QR batches and serials, public verification.
3. Certificate on the simulated ledger: two-person commit, revoke, amend, hash chain.
4. Quarterly production against QR serials.
5. Director's view: the Executive dashboard (`/app/demo/executive`), the Director's and the Auditor's dashboards, the MIS dashboard.
6. Five advisory AI helpers: model card, run, evidence, confidence explanation, recorded human decision.
7. Simulated email and SMS for payments, ledger, production and registration.
8. The auditor's trail.
9. **Registration** (brand and agency): file, fee, Finance confirms (new screen `/app/registrations/fees`), Programme recommends, Director approves, the Register, and a two-person revocation.
Plus exports (CSV, a real Excel workbook, a real PDF certificate with QR).

Menu: one list under Home in a fixed order (`MENU_ORDER` in `lib/runtimeRoutes.ts`).

## 5. Working rules that are not obvious from the code
- **Migrations:** never edit an applied one; add the next number. Many tests assert the highest migration (`max(installed_rank)`), so a new migration means raising those assertions.
- **Security-definer functions** must pin their `search_path` (V67 sets it for all of them; a test checks it). Do the same for any new one.
- **Database tests** (`*DatabaseTest`, tag `db`) create a throwaway schema on the local PostgreSQL, run the real migrations and the seeds, and drop it. They assert the real schema is untouched at the end.
- **Role checks** in demo modules go through `DemoAccess.holdsAll / holdsRole`, which respect the scope of a role; the oversight roles count only when held for all records.
- **The seeds count in the gate.** Run the full gate (`npm run local:check`) on a reset database without `demo:seed`, with the demo login undone (`node scripts/demo/login-setup.cjs undo`), `BEE_DEMO_LOGIN` unset, and Keycloak sessions of the sample users cleared. Run `mvn test` for the back end first. About 25 minutes. Do not edit repository files while it runs.
- **Hand-written client libraries:** `lib/client/csv.ts`, `xlsx.ts`, `pdf.ts` (with a QR encoder) have no dependencies on purpose.
- **Shared screen kit:** `components/app/kit/` (read panels, command panels, list tools with search, sort, paging, CSV and Excel). Reuse it; do not hand-roll tables.
- **Styling quirk:** `.demo-screen` rules in `app/globals.css` restyle headings, sections and buttons inside demo pages; where a page needs its own look it uses `role="heading"` elements and `!` Tailwind classes.
