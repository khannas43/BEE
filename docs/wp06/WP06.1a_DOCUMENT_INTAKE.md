# WP06.1a — Local test-report document intake

**Status:** Implemented locally on branch `wp06.1a-document-intake`; local checks pass (see Evidence). **Not independently reviewed or accepted.** WP06 and WP05 remain open; overall work-package count stays 1/11.

## Scope

- Local SHA-256 content-addressed store under `.local/documents` (git-ignored; `BEE_DOCUMENTS_STORE`, default 5 MiB via `BEE_DOCUMENTS_MAX_BYTES`).
- PostgreSQL metadata: `model_application_document` + immutable `model_application_document_version` (Flyway **V23**).
- Spring: `GET/POST /api/model-applications/{id}/documents`, `GET .../documents/{documentId}/versions/{versionId}/content`.
- Next BFF mirrors under `/api/runtime/...` with multipart forward (no re-encode) and PDF streaming.
- Upload: manufacturer or authorised agency with active filing scope on **own draft** only; brand rechecked at upload time.
- List/content: Spring `SlicePolicy` read scope; cross-org, unknown and malformed IDs → identical `404 not_found`.
- Versions preserve hash, size, media type, original filename, report label, optional tested-on / laboratory name (display only), uploader and time.
- PDF-only for now: magic bytes `%PDF-`, safe basename ending `.pdf`.
- Truthful label: `pending_local_verification` / verification note — no lab accreditation, malware clearance or BEE approval claim.
- No public downloads; authenticated scoped retrieval only.
- Idempotency: `Idempotency-Key` on upload; body hash over file bytes + metadata (not multipart boundary).
- Consistency: commit blob by hash first, then insert metadata; orphan blobs after DB failure are harmless; missing blob after metadata → `503`.
- UI: contextual **Test reports** card on the existing draft edit form (no new top-level menu).
- Contract artifact **0.5.0**.
