## What exists today

| Area | Current behaviour |
| --- | --- |
| Draft fields | Brand, category (`RAC` only) and model number. No laboratory, test date, standard or declared efficiency on the record. |
| Submit (`draft → fee_due`) | Checks brand authorisation, category, model-number format and version, then snapshots the provisional ₹24,000 fee. **No evidence or uniqueness rule.** |
| Uniqueness | None. Two drafts with the same brand and model number can both be submitted. |
| Test report | One logical `test_report` per application with immutable PDF versions (WP06.1a, in review). Laboratory name and test date are optional free text, display only. Status is `pending_local_verification`. |
| Laboratory accreditation | `master_lab_accreditation` exists (WP04.1): laboratory, category, body, certificate reference, status, effective period, provisional provenance. **Nothing consults it.** |
| Standard | `master_standard` exists (WP04.1); no application field refers to it. |

Source of the gap: INVENTORY R4 and G03/G04 (Detailed Design §5.3: intake validates brand, appliance configuration, model/family uniqueness, standard, laboratory accreditation, test dates and documents).

## Decisions

Recommended answers are mine, for the local demonstration. "If undecided" is what the build does when no answer is given, so work is never blocked.

| # | Question | Recommended | If undecided | Effect on the build |
| --- | --- | --- | --- | --- |
| 1 | Is at least one test report required before an application can be submitted? Per model, or per family? | Required: one report version per model application | Not required (today's behaviour); the screen shows the report as optional | New submit error `test_report_required` (422); the submit preview lists what is missing |
| 2 | Is the laboratory chosen from the accredited-laboratory master or typed as text? Must it hold an active accreditation for the category **on the test date**? | Choose from the master; submit refused unless an active accreditation covers the test date | Free text, no check; shown as "accreditation not checked" | New field `laboratory_code`; consult `master_lab_accreditation` by date; error `laboratory_not_accredited` |
| 3 | Is the test date required, can it be in the future, and is there a maximum age before filing? | Required, not in the future, no maximum age until BEE gives a figure | Optional, no check | New field `tested_on` on the application; error `test_date_invalid`; age limit is a master rule, not code |
| 4 | What makes a model unique: brand + model number across all non-rejected applications? Is a *family* (several models sharing one rating) in the first slice? | Unique on (brand, normalised model number) among applications that are not rejected; families deferred | No uniqueness rule | Unique index (new migration) and error `duplicate_model` (409); a returned application keeps its own number |
| 5 | Which standard and version applies, and does the applicant declare the efficiency figure (ISEER) or does the rating step derive it? | Standard picked from the master by test date; applicant declares ISEER, rating step recomputes and records both | No standard or declared figure captured | New fields; WP05.2 uses them as formula inputs |
| 6 | Besides the test report, which documents are required at submit (for example brand authorisation, licence copies), and are formats other than PDF allowed? | Test report only; PDF only; 5 MiB limit unchanged | Test report optional | Additional document kinds are WP06.2 work |
| 7 | May the applicant add or replace documents after a return (`returned` state), or only while the application is a draft? | Allowed while `returned`, never after resubmit | Draft only (today) | Upload rule extended to `returned`; affects the return and resubmit path of the first slice |
| 8 | Who checks that a report is genuine, and what outcomes exist? | IAME scrutiny records `verified` or `not verified` with a note; the system never claims verification by itself | `pending_local_verification` stays on every report | Scrutiny action in WP05.2; status values in WP06.2 |

Not in this package: the fee amount and its source (provisional, separate BEE decision), quarantine and malware policy, retention, and the document audit package (WP06.2–WP06.3).

5. This is the remainder of WP05.1 in the plan's own estimate (55 person-days in total); no new figure is claimed.
