# Demo S6: five AI use cases (local demonstration, advisory only)

**Real:** Spring module `ai` (`/api/demo/ai`), migrations V62 to V64, stored append-only runs (model version, data version = hash of the input rows, evidence, confidence), human dispositions (accept/override/reject, reason required for the last two, override stored beside the model's output), audit rows. Compliance risk, production anomaly and rating trends are computed from live portal tables (returns, rejections, ratings, fee confirmations; production and QR tables when present). Helpdesk is TF-IDF cosine over `ai_kb`; extraction reads text from the stored PDF (plain or Flate streams, no OCR) and compares with the application.
**Simulated / synthetic:** all models are transparent rules or statistics, not machine learning; `ai_demo_entity`, `ai_demo_production` (used when `production_row` is absent or empty), `ai_demo_rating`, `ai_kb` (20 FAQ articles) and `ai_demo_report_text` (used when the PDF has no readable text) are synthetic, seeded by `local/seed/demo/s6_ai.sql`. Weights and thresholds are the owner's assumptions, not BEE rules.
**Never:** nothing writes to an application, certificate, fee or decision record.
**Routes:** GET `ai/models`; GET/POST `ai/{useCase}/runs`; GET `ai/{runId}`; POST `ai/{runId}/disposition` (the dispatcher allows three segments, so the run id replaces `runs/{id}`). Roles: programme, reviewer, admin run most; helpdesk runs helpdesk-assist; director/secretary run trends; auditor reads only; others denied.
**Demo:** bee.programme: Compliance risk, Run, open the top row's contributions and evidence, Override with a reason. Production anomaly: flags the spike series. Rating trends: slope and 95% band. Helpdesk assist (bee.helpdesk): ask about paying a fee, edit the draft (override), then a nonsense question to see escalation. bee.reviewer: Document extraction for LOCAL-MA-0004, confirm each field. Reload: history and dispositions persist. bee.auditor reads, cannot record.
