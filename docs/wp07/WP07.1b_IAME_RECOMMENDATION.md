## What it does

`POST /api/model-applications/{id}/iame-recommendation` (browser route `/api/runtime/model-applications/{id}/iame-recommendation`) moves an application from `iame_scrutiny` to `bee_scrutiny` when the assigned IAME officer records a finding on the uploaded test report and a note. The screen is `/app/model-label/iame-scrutiny`, in the sidebar for an IAME identity only.

| Rule | Behaviour |
| --- | --- |
| Who | The reviewed slice rule `SliceAction.IAME_RECOMMEND` through `SlicePolicy.check`: an IAME role with scope `assigned`, the `iame_scrutiny` source state, the officer's own assignment at that stage, and nobody who already acted at another stage. A caller with another role gets 403 `role_not_permitted`. |
| What the officer sees | Only applications assigned to them at the stage they are in. Any other application is the same 404 `not_found` as an unknown one, including one that has moved on. |
| Separation | A caller who belongs to the application's own organisation, or who submitted it or took an earlier step (for example the Finance confirmer), gets 403 `segregation_refused`. |
| Input | `version`, `verification` (`verified` or `not_verified`), `note` (1 to 500 characters after trimming, no control characters). |
| Both findings forward | Either finding moves the application to `bee_scrutiny` with the note. Returning it to the applicant is a later step (BL-097). |
| Atomic write | One transaction: the guarded state change, an append-only `model_application_transition_event`, an append-only `model_application_iame_recommendation`, the closing of the officer's assignment, and the assignment of the next reviewer. |
| Next reviewer (provisional D2) | The active reviewer account with the fewest open `bee_scrutiny` assignments, ties by id. If none is available, 409 `assignee_unavailable` and nothing is written. |
| Idempotency | A key is required. A repeat with the same body returns the stored **receipt** (header `Idempotency-Replayed: true`); a different body under the same key is 409 `idempotency_key_conflict`. The answer is a receipt, not an application view, because the officer loses access with the move. |
| Honest labelling | The screen says the finding is the officer's own; the system makes no accreditation, authenticity or malware claim about a report. |

## What changed

- **Flyway V26:** the append-only `model_application_iame_recommendation` table (triggers, runtime role INSERT and SELECT only, checks on the finding and the note) and the disposable-cleanup function extended to remove its rows.
- **Spring:** `gov.bee.api.iame` (controller, service, repository), generated by the scaffolder and then implemented. No new error codes.
- **Contract 0.8.0:** the operation on both layers, `IameRecommendationRequest` and `IameRecommendationReceipt`, and the per-feature BFF module `lib/server/contracts/iame-recommendation.ts`. The `segregation_refused` message was made general ("cannot take this step") because it is now shared by two steps.
- **Screen:** `IameScrutiny` on the kit (`useRuntimeRead`, `ReadPanel`, `DataTable`, `useCommand`, `CommandPanel`), a runtime route and menu entry. `ApplicationDocuments` was extracted from the model dashboard so both screens list the test reports.
- **Tooling bug found and fixed on the second use of the scaffolder:** `addToRouteEnum` matched the word `route` inside the schema's `required` list and wrote the new routes into the `layer` and `method` enums of the request-log schema, which failed `SpringContractTest`. It now matches the property key. `new-feature.test.mjs` asserts this.
