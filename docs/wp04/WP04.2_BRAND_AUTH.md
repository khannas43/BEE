# WP04.2a — Brand ownership and agency authorisation (backend foundation)

Status: **accepted as a local backend foundation after integration review; WP04 remains open at 1/11.** Branch `wp04.2-brand-auth` is rebased onto the accepted V5 master-supersession correction (`ca4ccf8`). V6 has been applied and seeded on the shared local `bee_app.app` schema in order after V5. This increment does not close brand/agency registration (R1) or grant any screen-matrix proposal.

This activity persists brand ownership and agency authorisation records, and gives Spring an internal resolver for “is this agency authorised for this principal’s brand on this date?”. No browser screen, API route, registration submission/approval workflow, server role grant, fee logic or rating logic is included. Existing `model_application` rows and the `brand_name` text column are unchanged. Model-application policy (`SlicePolicy`) is unchanged: submissions remain denied for brand permission until a later reviewed slice wires these records.

**Nothing here is BEE-approved.** Seeded rows are `synthetic`. They must not be described as official brand registrations or BEE authorisations.

## 1. Schema (`V6__brand_agency_authorisation.sql`)

Flyway version **V6** follows V5 master supersession. Both the throwaway test schemas and the shared local schema migrate contiguously through V6. The shared schema was migrated only after this branch was rebased onto V5.

### `brand`

| Column | Meaning |
| --- | --- |
| `id` | uuid |
| `name` | Display name; unique per owner organisation |
| `owner_organisation_id` | FK → `organisation`; must be kind `manufacturer` |
| `status` | `active`, `suspended` or `revoked` |
| `source_reference`, `verification_status`, `note` | Provenance (`synthetic` / `provisional` / `verified`) |
| `recorded_at` | Insertion time |

### `agency_authorisation`

| Column | Meaning |
| --- | --- |
| `id` | uuid |
| `agency_organisation_id` | FK → `organisation`; must be kind `agency` |
| `principal_organisation_id` | FK → `organisation`; must be kind `manufacturer` and **must own** `brand_id` |
| `brand_id` | FK → `brand` |
| `valid_from`, `valid_to` | Half-open `[from, to)`; `NULL` `valid_to` is open-ended |
| `status` | `active` or `revoked` |
| Provenance columns | As for `brand` |

Database guards:

- **Referential integrity** on organisations and brand.
- **Principal owns brand** — insert/update trigger refuses a principal that is not the brand’s owner (`23514`).
- **Organisation kinds** — manufacturer owner/principal, agency as agency (`23514`).
- **No contradictory active periods** — for the same agency and brand, active `[from, to)` ranges must not overlap (`23P01`). Touching periods are allowed. An open-ended active grant blocks any later start. Revoked rows do not participate. Writers take a transaction advisory lock on `(agency, brand)` so concurrent grants cannot both pass.

## 2. Date boundary convention

A grant covers date `d` when `valid_from <= d` and either `valid_to` is null or `d < valid_to`. Same half-open convention as WP04.1 masters. The caller supplies an IST calendar date.

## 3. Spring API (internal)

Package `gov.bee.api.brand`. No controller.

- `BrandAuthRepository` — read brand by id / active ownership; resolve active authorisation at a date; support denial inspection (latest row, other-brand presence).
- `BrandAuthService`:
  - `ownedBrand(brandId, ownerOrganisationId)` — active brand owned by that organisation;
  - `agencyAuthorisation(agency, brand, principal, at)` → `AUTHORISED`, or denial `NO_AUTHORISATION` / `EXPIRED` / `REVOKED` / `WRONG_BRAND` / `PRINCIPAL_MISMATCH` / `BRAND_INACTIVE`.

Scope is always the named brand **and** principal. Wrong brand (agency has a grant for another brand of that principal), expired period, revoked status, missing row and principal/ownership mismatch all deny.
