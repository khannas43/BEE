# WP08.1d — The menu follows the permission

**Status:** Implemented locally on branch `menu-by-permission`; the full local gate passes (see Evidence). **Not independently reviewed or accepted.**

**Provisional local rules, not BEE rules.** This completes the owner's A1/C1/A2 assumption that the permission to change a fee rule or a rating scheme "can be assigned to another role later" (4 October 2026): until now giving a role the permission worked, but its menu entry still followed the Administrator role.

## What it does

`GET /api/me` now also reports `capabilities`: the permissions that the person's effective roles hold (from `capability_grant`), for example `fee_rule_manage`. A menu entry can name a role (as before) or a permission. The Fee rules and Rating schemes entries now name the **permission**, so:

- the Administrator, whose role holds both, sees both;
- a role that is given a permission by a database row sees that screen's entry on its next page load, and loses it when the row is removed;
- everyone else sees neither.

The menu is a hint only: it never grants anything. Spring still decides every read and every action from the database, and a person whose role does not hold the permission gets 403 whatever the menu shows.

## What changed

- **Spring:** `IdentityRepository.capabilities(roles)`; `MeController` returns `capabilities` (sorted, each once).
- **Contract 0.20.0:** `Me.capabilities` (required array of strings), with the examples updated.
- **Web:** `RuntimeRoute.navCapabilities`; `runtimeNavFor(roles, capabilities)`; the sidebar passes the capabilities; the two administration routes name their permission and no role.
- **Tests:** a database test that the permissions follow the roles that hold them (and each is listed once), a contract test for `/api/me`, unit tests for the menu, and four menu checks added to each of the fee-rule and rating-scheme live checks (80 and 78 checks): Finance gets the entry once its role is granted the permission and loses it once removed; the applicant never has it.
