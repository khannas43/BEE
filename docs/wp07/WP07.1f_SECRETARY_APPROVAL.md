# WP07.1f — The Secretary gives final approval (first slice step 7)

**Status:** Implemented locally on branch `wp07.1f-secretary`; local checks pass (see Evidence). **Not independently reviewed or accepted.** WP05.2 and the first slice remain open; the work-package count stays 1/11.

**This completes the first slice's happy path:** an application can now go from a manufacturer's draft to `approved`, through Finance, the IAME officer, the Reviewer, Programme, the Director and the Secretary, with a different person at every step. It is still a local demonstration on provisional rules: the fee (decision A1), the star bands (A2, a local demonstration, not a BEE rating) and the Director-can-be-final assumption (D1, an owner assumption) are all stand-ins, and the journey has no return, resubmit or rejection path yet.

## What it does

`POST /api/model-applications/{id}/secretary-approval` (browser route `/api/runtime/model-applications/{id}/secretary-approval`) moves an application from `secretary_approval` to `approved`. It shares the screen `/app/model-label/director-approval` with the Director, as the screen matrix lays it out: each role sees only its own stage, and the action offered follows the application's state. The sidebar entry is shown to Director and Secretary identities.

| Rule | Behaviour |
| --- | --- |
| Who | The reviewed slice rule `SliceAction.SECRETARY_APPROVE` through `SlicePolicy.check`: a Secretary role with scope `all`, the `secretary_approval` source state, and nobody who already acted at another stage. Another role gets 403 `role_not_permitted`. |
| What the Secretary sees | Only applications in the `secretary_approval` stage, with the rating, the evidence and the test reports. An application that has moved on is the same 404 `not_found` as an unknown one. |
| Separation | A caller from the application's own organisation, or who took any earlier step (so not the Director who recommended it, and not Finance, the IAME officer, the Reviewer or Programme), gets 403 `segregation_refused`. |
| Input | `version` and `note` (1 to 500 characters after trimming, no control characters). |
| Atomic write | One transaction: the guarded state change, an append-only `model_application_transition_event`, and an append-only `model_application_secretary_approval` (one per application). |
| Director-final applications | An application the Director's recommendation already made final (decision D1, an owner assumption) is already `approved` and never reaches this step; a test proves the Secretary has nothing to do for it. |
| Idempotency | A key is required. A repeat with the same body returns the stored **receipt** (header `Idempotency-Replayed: true`); a different body under the same key is 409 `idempotency_key_conflict`. |

## What changed

- **Flyway V30:** `model_application_secretary_approval` (append-only, one per application) and the disposable-cleanup function extended.
- **Spring:** `gov.bee.api.secretary` (controller, service, repository). No new error codes.
- **Contract 0.12.0:** the operation on both layers, `SecretaryApprovalRequest` and `SecretaryApprovalReceipt`, and `lib/server/contracts/secretary-approval.ts`.
- **Screen:** `DirectorApproval` now serves both stages: the action is the Director's for `director_review` and the Secretary's for `secretary_approval`. The shared parts keep their `director-*` test ids (BL-113).
- `runtimeNavFor` now gives the Secretary the approval entry; the read-ui test that listed the Secretary as having no entry was updated (Admin and Auditor stand in for "no entry").
