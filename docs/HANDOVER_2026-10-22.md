# BEE portal: closing hand-over note, 22 October 2026

The demonstration to BEE officials is done and went well. This note closes the project for now and supersedes `HANDOVER_2026-10-19.md` for the state of the code. Read it, then `README.md`, then `docs/demo/DEMO_RUNBOOK_BEE_OFFICIALS.md`. Local demonstration only: all data is synthetic; the Fabric ledger, payment gateway, e-mail, SMS, OTP, KYC and AI helpers are simulated and labelled on screen.

## 1. Where the code is
- Worktree `~/Developer/BEE-integration`, branch `integration/wp3-c3`, about 200 commits ahead of `main` (`06f51d5`). **Nothing is pushed and `main` is untouched.** Merging or pushing needs the owner's word.
- Other worktrees and the old bundles (`BEE-portal-2026-10-17.*`, `-19.*`) are kept as history.
- Migrations V1 to V89. Applied migrations are immutable; add V90 next.
- OpenAPI contract 0.38.2. The demo API family `/api/demo/**` is outside it on purpose (`docs/demo/API.md`).

## 2. What was added after the 19 October note
- **Product testing journey** (BEE officer and manufacturer): risk-weighted random shortlist from compliance risk, anomalies and customer grievances; officer approval with remarks; test cases through selected, procured, at lab, result in, closed; manufacturer sees results and grievance counts and categories only, never the complainant.
- **Sign-in activity** per manufacturer and one consolidated BEE officer view, with search and date range.
- **Production details** with serials, label fee and payment, linked to the quarterly submission; financial-year selector.
- **Architecture** page (100 percent open-source stack, no licences) and **Security** page (planned controls, OWASP and MeitY aligned; cards only).
- **Staff notices** fix on the notifications page.
- **Company registration aligned with SOP 1.1** (option A, BL-308): nine steps, SOP documents, fee lines (small scale 5,000; large scale 5,000 plus 3,00,000 deposit).
- **Option B, the SOP sequence** (BL-309), **now on in the running demo**: public form with captcha gives a Reference ID; "Pay Registration Fee" with Reference ID, captcha, a 6-digit code (3 minutes; locked 2 hours after 3 wrong tries), payment (BillDesk, Razorpay or direct transfer), credentials shown after payment. Switch: `NEXT_PUBLIC_BEE_REGISTRATION_FLOW=sop`; leave it unset to return to option A.

## 4. Data, and what not to run
- The live data (Ravik with blank new fields, the seeded cases, product testing, production history) is backed up in `~/Developer/handover/demo-state-2026-10-22/` (`pg_dumpall.sql`, restore steps inside).
- **`npm run demo:prepare-approval`, `demo:reset`, `local:reset`, `local:reset:identity` and `local:check` wipe or rebuild the data.** Use them only when the data is not needed, or restore from the dump afterwards.
- `demo:prepare-approval` and the older scripts (`prepare-ravik24-submission.cjs`, `prepare-hold-cases.cjs`, `c1-manufacturer-onboarding-journey.cjs`) still use the pre-SOP fields and documents; fix them first (BL-308).
