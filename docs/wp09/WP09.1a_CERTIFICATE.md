# WP09.1a — The certificate issued at approval

**Status:** Implemented locally on branch `wp09-certificate`; the full local gate result is in Evidence. **Not independently reviewed or accepted.**

**Provisional local rules, not BEE rules.** The owner's defaults D7 to D9 of 5 October 2026 ([BEE_DECISIONS.md](../BEE_DECISIONS.md), [WP09_PLAN.md](WP09_PLAN.md)). Every certificate is a **local demonstration**, not issued by BEE, and says so.

## What it does

When an application becomes `approved`, a certificate is issued **in the same transaction**: by the Secretary's final approval, or by a Director's recommendation that is final for the category. If issuing fails, the approval does not happen.

| Rule | Behaviour |
| --- | --- |
| Registration ID | `BEE/<category>/<year>/<number>`, numbered per category and year from 10001. The number is allocated under a row lock, so concurrent approvals never share one. |
| Validity | Three years from the approval date (India date): the last valid day is the day before the third anniversary. Renewal is not built. |
| What it keeps | The brand, model, organisation name, stars, declared and verified efficiency figures and the rating scheme it was issued on, so it never changes with later records. |
| Status | `valid`, `expired` or `not_yet_valid`, worked out from the dates when the certificate is read. Revoked is designed in but not built. |
| Who sees it | The applicant's organisation, on the application detail read; the dashboard shows a card. (An approved application is closed to officers, as before.) |
| Writes | One database function, `issue_certificate`, is the only way the runtime login can create a certificate; it cannot write the table or the numbers. The table is append-only. |

## What changed

- **Flyway V37:** `certificate_allocator`, `certificate` (append-only), `issue_certificate()`, grants, and the disposable-cleanup function extended to remove certificates.
- **Spring:** `SecretaryApprovalRepository.approve` and `DirectorRecommendationRepository.recommend` (final) call the function; the detail read carries `certificate` once approved.
- **Contract 0.22.0:** `ApplicationCertificate` on the application detail read.
- **Web:** `CertificateCard` on the dashboard, the BFF validator, the client type.
- **Tests:** database tests in `SecretaryApprovalDatabaseTest` (the certificate and its facts, the Director-final path, consecutive numbers and concurrent approvals, append-only and the runtime login's limits, cleanup), `CertificateViewTest`, a contract test of the detail read, `certificate.test.mjs`, two screen tests, and certificate checks added to the Secretary live check (71 checks).
