# WP03.2 Cursor brief — authenticated model reads through the Next.js BFF

Status: next increment brief, not implementation or acceptance. Branch from the commit containing this brief on `wp03.1-api-contract` (reviewed parent `d4eba38`). WP01 remains 1/11 accepted; WP02 and WP03 remain open.

## Objective

Implement browser-facing GET `/api/runtime/model-applications` and GET `/api/runtime/model-applications/{id}`. The browser calls only these same-origin Next.js routes; Next retrieves the server-held session and calls the existing Spring list/detail endpoints with its access token. Spring alone decides organisation, role, assignment and current-stage read scope. No menu or screen-matrix proposal is a grant.

Reuse WP03.1's correlation ID, no-store headers, fixed error body, strict per-operation success validator and status/code allowlist. Add the two BFF operations to `docs/wp03/bee-local-api.openapi.json` and remove only their deferred entries. Version the artifact in the same commit and test that code and artifact agree. Validate list count, each item and the detail object at every depth; an unknown field, malformed response, unknown status/code or non-JSON body must become a fixed 502 without upstream text reaching a response, redirect or log.

Anonymous, expired or forged browser sessions return the documented 401. A browser `Authorization` header is ignored. A Spring refusal retains only its documented status/code with the contract message; Spring outage becomes 503 without destroying a valid portal session. Cross-organisation, unknown, malformed and stale-assignment detail IDs must have an indistinguishable 404 status/body shape (apart from a fresh correlation header). Do not pre-disclose record existence through a Next-side UUID validator, cache or redirect.

Do not add model writes, approvals, historical read, route-policy grants, a separate gateway or external services. Idempotency and 409 are for write commands; record the key scope, replay and conflict contract now, but defer executable behavior to the first reviewed write endpoint under WP05/WP07. Do not build an unused idempotency store.
