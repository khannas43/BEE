## 1. Authority

Keycloak identifies the caller; Spring's database decides. For every model-application request Spring resolves the token subject to a `Caller`:

| Record | Must be | Otherwise |
| --- | --- | --- |
| `user_account` for the token `sub` | present, `status = 'active'` | 403 `no_active_account` |
| `role_assignment` | `active`, inside `valid_from`/`valid_to`, **and** the same role in the token's realm roles | 403 `no_effective_role` |
| `organisation_membership` | `active`, inside its validity, organisation `active` | own-org roles read nothing |
| `assignment` (`subject_type = 'model_application'`) | `active`, for this user and this application | assigned-scope roles read nothing for it |

A token role is necessary but never sufficient, and a role counts only with the exact scope the rule names (for example, a Reviewer grant with scope `all` is not honoured). The token's `organisation` claim is ignored; the local check clients set it to the wrong organisation on purpose.

Policy decision for this local slice (30 September 2026):
- A brand owner does **not** see an application filed by an agency merely because it owns the brand. WP04 must supply an explicit agency authorisation and a reviewed visibility rule before adding this read.
- Internal officers do **not** retain model-application read after their stage has passed. Assigned officers need an active assignment matching the application's current stage; later historical access needs a separately reviewed rule.
- Auditor has **no** model-application read yet. WP10/audit work must define a scoped, read-only evidence view before granting it.

These decisions keep the first-slice policy narrow. They do not decide the eventual production policy or grant any of the 540 matrix proposals.

## 5. Seed fixtures

`local/generate-fixtures.cjs` adds four synthetic applications as **seeded states, not transitions**. Nova has `LOCAL-MA-0001` (`draft`), `LOCAL-MA-0002` (`fee_due`) and `LOCAL-MA-0004` (`bee_scrutiny`). PixelCert has `LOCAL-MA-0003` (`iame_scrutiny`). There are two assignments: IAME on `LOCAL-MA-0003` (active), and Reviewer on `LOCAL-MA-0004` (inactive). The seeded Reviewer role scope changes from `all` to `assigned`, to match §6 and ADR-001 D-RT3. `npm run local:reset` reloads the fixtures without touching Keycloak or the volume.
