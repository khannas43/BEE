# WP07.1d — Programme computes and records the rating (first slice step 5)

**Status:** Implemented locally on branch `wp07.1d-rating`; local checks pass (see Evidence). **Not independently reviewed or accepted.** WP05.2 and the first slice remain open; the work-package count stays 1/11.

**This is a local demonstration, not a BEE rating.** Decision A2 (the approved formula, its inputs and the thresholds) is unanswered. The five star bands below are invented placeholders so the journey can be shown end to end. Every rating this step writes is marked `basis = local_demo`, the receipt says `localDemoRating: true`, and the screen says "not a BEE rating". Nothing here may be shown as an official rating.

## What it does

`POST /api/model-applications/{id}/rating` (browser route `/api/runtime/model-applications/{id}/rating`) moves an application from `rating` to `director_review` when Programme enters the efficiency figure they verified from the test report and the server computes the stars. The screen is `/app/model-label/rating-calculation`, in the sidebar for a Programme identity only.

| Rule | Behaviour |
| --- | --- |
| Who | The reviewed slice rule `SliceAction.COMPUTE_RATING` through `SlicePolicy.check`: a Programme role with scope `all`, the `rating` source state, and nobody who already acted at another stage. Another role gets 403 `role_not_permitted`. |
| What Programme sees | Only applications in the `rating` stage. An application that has moved on is the same 404 `not_found` as an unknown one. |
| Separation | A caller from the application's own organisation, or who took an earlier step (Finance, the IAME officer, the Reviewer), gets 403 `segregation_refused`. |
| Input | `version` and `verifiedIseer` (decimal text, up to two digits and two decimals, above zero). The applicant's declared figure is kept beside it and never replaced. |
| The stars | The highest band of the demonstration scheme in force today (India date) whose minimum the figure reaches: 3.30 gives 1 star, 3.50 gives 2, 4.00 gives 3, 4.50 gives 4, 5.00 gives 5. Below 3.30 is 422 `rating_below_threshold` and nothing is written. No scheme in force is 422 `rule_not_available`. |
| Atomic write | One transaction: the guarded state change, an append-only `model_application_transition_event`, and an append-only, versioned `model_application_rating` (rating version, scheme, declared and verified figures, stars, who computed it). |
| Next stage | No officer is assigned: Directors read the `director_review` stage by role. |
| Idempotency | A key is required. A repeat with the same body returns the stored **receipt** (header `Idempotency-Replayed: true`); a different body under the same key is 409 `idempotency_key_conflict`. |

## Why the master formula table is not used

`master_rating_formula` can only be marked computable for a BEE-verified version, and the existing tests prove the database refuses anything else. That guard is the project's protection against showing an unverified rating as real, so it was left untouched (a test asserts no formula is computable or verified). The demonstration bands live in a separate, append-only table, `rating_demo_band`, which the runtime role can only read. When BEE answers A2, a verified master formula replaces it (BL-104).
