## What it does

`POST /api/model-applications/{id}/reviewer-forward` (browser route `/api/runtime/model-applications/{id}/reviewer-forward`) moves an application from `bee_scrutiny` to `rating` when the assigned Reviewer records a note and forwards it. The screen is `/app/model-label/bee-scrutiny`, in the sidebar for a Reviewer identity only.

| Rule | Behaviour |
| --- | --- |
| Who | The reviewed slice rule `SliceAction.REVIEWER_FORWARD` through `SlicePolicy.check`: a Reviewer role with scope `assigned`, the `bee_scrutiny` source state, the reviewer's own assignment, and nobody who already acted at another stage. Another role gets 403 `role_not_permitted`. |
| What the reviewer sees | Only applications assigned to them at the stage they are in. Any other application, including one that has moved on, is the same 404 `not_found` as an unknown one. |
| Separation | A caller from the application's own organisation, or who submitted it or took an earlier step (Finance, the IAME officer), gets 403 `segregation_refused`. |
| Input | `version` and `note` (1 to 500 characters after trimming, no control characters). |
| Atomic write | One transaction: the guarded state change, an append-only `model_application_transition_event`, an append-only `model_application_reviewer_forward`, and the closing of the reviewer's assignment. |
| Next stage | No next officer is assigned: Programme reads the `rating` stage by role (read scope `all`, stage `rating`). |
| Idempotency | A key is required. A repeat with the same body returns the stored **receipt** (header `Idempotency-Replayed: true`); a different body under the same key is 409 `idempotency_key_conflict`. |

## What changed

- **Flyway V27:** the append-only `model_application_reviewer_forward` table (triggers, runtime role INSERT and SELECT only, a check on the note) and the disposable-cleanup function extended to remove its rows.
- **Spring:** `gov.bee.api.reviewer` (controller, service, repository), from the scaffolder and then implemented. No new error codes; there is no `assignee_unavailable` for this step.
- **Contract 0.9.0:** the operation on both layers, `ReviewerForwardRequest` and `ReviewerForwardReceipt`, and `lib/server/contracts/reviewer-forward.ts`.
- **Screen:** `ReviewerScrutiny` on the kit, built like the IAME screen, with the test reports listed through the shared `ApplicationDocuments`.
- The scaffolder's request-log schema fix from WP07.1b worked unchanged on its third use.
