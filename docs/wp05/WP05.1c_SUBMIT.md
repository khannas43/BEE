- `GET` / `POST /api/model-applications/{id}/submit` (Spring) and `/api/runtime/model-applications/{id}/submit` (BFF).
- Filing manufacturer or authorised agency on **own** draft only; brand/agency recheck from Spring DB at submit time.
- Category, performance-test standard and `new_model` fee rule must exist for submission date; missing rule → `422 rule_not_available` (fail closed).

- UI: save-before-submit when the edit form is dirty; confirm shows persisted `draftSummary` and provisional fee; stored fee on GET list/detail after reload.
- V10 append-only triggers on submission event and fee tables; local disposable cleanup via `app.app_disposable_model_cleanup()` only.

## Re-review of `e6331b9` (2 October 2026)

The five original fixes are present, and the independent full `npm run local:check` run finished **221 passed, 2 failed**. The repaired unmatched-route probe passed. Remaining corrections:

1. **Append-only bypass remains open.** The Spring runtime and test harness use the `bee_app` database login. V10's trigger trusts `current_setting('bee.test_cleanup') = 'allow'`, which that login can set directly; `app_disposable_model_cleanup(uuid[])` accepts arbitrary application IDs and V10 does not revoke its default execution grant. The runtime database role can therefore delete any submitted application's event and fee through the cleanup function. Separate runtime and maintenance privileges, restrict cleanup to disposable records, and test that the runtime login cannot invoke or imitate cleanup. V10 has been applied; use a later migration and role/setup changes.
2. **Contract coverage gate fails.** `coverage.every-documented-pair` reports 181/220 pairs evidenced, leaving 39 new submit operation/status/code pairs uncovered. The focused submit runner does not feed the coverage inventory. Add genuine live, stand-in, MockMvc or unit evidence for each documented pair; do not mark uncovered pairs as covered or remove truthful statuses merely to pass.
3. **Database suite gate fails.** `masters.db-tests` exits 1 because `BrandAuthDatabaseTest.flywayOnThrowawayIncludesV5AndV6AndDoesNotTouchApp` still expects version 8 after V9/V10. Update the test's migration expectation and prove its shared-schema isolation claim.
4. **Dirty form after preview.** `openSubmitConfirm` checks dirty fields, but `confirmSubmit` does not recheck them. Editing a field after opening the confirmation can still submit the persisted values. Close or disable confirmation on edit and test that sequence.

The implementation's focused submit and contract checks were not repeated in this review. WP05.1c, WP05.1 and WP05 remain unaccepted; accepted work packages stay 1/11.
