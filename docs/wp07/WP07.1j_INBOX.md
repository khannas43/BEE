# WP07.1j — The inbox and My approvals (Wave 1)

**Status:** Implemented locally; the full local gate passes (see Evidence). **Not independently reviewed or accepted.** WP05.2 and the first slice remain open; the work-package count stays 1/11.

**Provisional local rules, not BEE rules.** What counts as "waiting for you" is the first slice's own stage ownership, not a BEE decision.

## What it does

`/app/workflow/personal-inbox` ("My work") and `/app/workflow/my-approvals` list the applications waiting for the signed-in person, each with what to do and a link to the screen where it is done.

| Person | Waiting for them |
| --- | --- |
| Applicant (manufacturer, agency) | A draft ("Finish and submit") and a returned application ("Edit and resubmit"). Their applications in any other state are not theirs to act on. |
| Finance | Applications with the fee due. |
| IAME, Reviewer, Programme | The application at their own stage. |
| Director, Secretary | The application at their decision (shown in the inbox and on My approvals). |

Approved and rejected applications are nobody's task. The menu shows both entries from the Spring identity ("My approvals" for the Director and Secretary only).

**No backend and no contract change.** The screens use the same scoped list read the stage screens use, so nothing appears that Spring would not already return; the task mapping (`components/app/workflow/workTasks.ts`) only chooses the action and the link. It grants nothing, and each stage screen and Spring check the action again.
