## Re-review (1 October 2026)

The original five blockers are addressed. Independent `api:test`, `web:test` (62/62), matrix (24/24) and access audit (9/9) passed; the live 30/30 and full 223/223 checks are reported from the implementation run, not repeated in this review. Two correctness issues remain:

1. **Allocator rewind on seed.** `local/seed/seed.sql` updates `model_application_reference_allocator.next_value` to `MAX(reference)` on every seed. If a higher reference was allocated then its draft was removed (as in the disposable write check), a later seed moves the allocator backwards and reuses a previously issued reference. Keep `next_value` at least its current value (for example `GREATEST` in the upsert) and test seed replay after allocation/removal. V8 is applied; do not edit its migration.
2. **Unsafe legacy edit default.** An existing draft with `brand_id IS NULL` loads in the edit form. The eligible-brands effect defaults to the first option, and PATCH then sends that brand ID. If the legacy `brand_name` refers to another brand, the edit silently relinks ownership and bypasses the server’s unique-name reconciliation. Do not auto-select a brand for an unlinked legacy draft. Either omit `brandId` on PATCH and let Spring's unique eligible-name match decide, or require the user to explicitly select and confirm a brand when there is no unique match. Test the multiple-brand/mismatched-name case and prove that the stored brand and principal cannot change silently.
