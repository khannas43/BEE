## 2. Request log format and retention

One JSON object per line, `additionalProperties: false` on every line type:

| Line | Fields |
| --- | --- |
| `request` (Spring and Next.js) | `ts`, `layer` (`api`/`web`), `event`, `correlationId`, `method` (fixed set or `OTHER`), `route` (documented template, `unmapped` or `/api/{unmatched}`), `status`, `outcome` (`ok`, a contract error code, a sign-in redirect code, or `unlisted`), `durationMs` |
| `upstream` (Next.js → Spring) | as `request`, `route` one of the 4 Spring templates |
| `identity` (Next.js → Keycloak) | `ts`, `layer`, `event`, `correlationId`, `operation` (`discovery`, `jwks`, `token.code`, `token.refresh`, `logout`), `status` (0 if unreachable), `outcome` (`ok`, a standard OAuth error code, `refused` or `unreachable`), `durationMs` |

Never written: raw paths or IDs (route templates only), query strings, authorization codes, `state`, tokens, cookies, request or response bodies, Keycloak `error_description`, user names, e-mail addresses, display names, subjects. Unexpected method or outcome values are reduced to `OTHER` or `unlisted`. `next.config.ts` sets `logging.incomingRequests: false`, because Next dev otherwise printed raw request URLs (including the callback's `code` and `state`) to `web.log`.

| File | Writer | Rotation | Bound |
| --- | --- | --- | --- |
| `api-requests.jsonl` | Logback `SizeAndTimeBasedRollingPolicy` (`backend/src/main/resources/logback-spring.xml`) | daily and at 5 MB | 7 days, 20 MB total, old files removed at start |
| `web-requests.jsonl` | `lib/server/requestLog.ts` | at 5 MB | 3 rotated files, none older than 7 days |

The `contract-artifact` test fails if the retention values in the schema, `logback-spring.xml` and `requestLog.ts` disagree. The console logs (`api.log`, `web.log`) are recreated on each start and carry no request lines.

## 3. Correlation evidence (browser → Next.js → Spring)

Every row is one correlation ID sent by the check (or issued by the portal) and found, in order, in the lines shown. "api: none" is checked, not assumed.

| Case | Web lines (Next.js) | Spring lines | Check |
| --- | --- | --- | --- |
| Successful read (`/api/runtime/me`, list, detail) | upstream 200 ok → request 200 ok | request 200 ok | `correlation.sign-in-and-reads`, `bff.correlation` |

| Sign-in failure (inactive role) | identity `token.code` 200 ok → upstream 403 `no_effective_role` → identity `logout` 204 ok → request callback 303 `no_effective_role` | request 403 `no_effective_role` | `correlation.sign-in-and-reads` |
| Callback without login (planted code/state) | request callback 303 `login_expired` only | none | `correlation.sign-in-and-reads` |
| Denials (role revoked, membership expired, inactive account) | upstream 403 code → request 403 code | request 403 code | `bff.correlation`, `contract.inactive-account` |
| Malformed, unsafe and other-organisation IDs | upstream 404 `not_found` → request 404 `not_found` | request `/api/model-applications/{id}` 404 | `bff.correlation` |
| Unsafe correlation ID | portal issues a UUID, used on every line | same UUID | `correlation.sign-in-and-reads`, `logs.planted-request-values` |

| Refused refresh (Keycloak session ended) | identity `token.refresh` 400 `invalid_grant` → request 401 `session_expired`, no upstream | none | `bff.correlation-refresh` |
| Spring outage | upstream 503 `api_unreachable` → request 503 `api_unreachable` (health too) | none | `correlation.outage`, `bff.correlation` |
| After Spring restart | upstream 200 → request 200 | request 200 | `correlation.outage` |
| Logout | identity `logout` 204 ok → request 200 ok | none | `next.logout` |
| Keycloak unreachable (sign-in start, refresh) | identity `discovery` 0 `unreachable` → request 303 or 503 `identity_unavailable` | none | unit: `request-log.test.mjs` |

### Mutations caught

Each mutation was applied, shown to fail, and reverted. The checks then passed again.

1. **Log leak.** `logged()` was changed to add the raw query string to each Next.js request line.
   - `web:test` failed: `every line written in this file matches the documented format…`.
   - `local:contract` failed 3 checks:
     - `logs.planted-request-values` found the planted query, code and state in a log;
     - `logs.structured-format` reported lines matching none of the line types;
     - `logs.no-sensitive-data` found the callback code and state.
   - After reverting, the 75 mutated lines were deleted from the local `web-requests.jsonl`, because they held the twins' already-redeemed authorization codes.
2. **Contract drift.** Spring's `not_found` message was changed.
   - `api:test` failed in `SpringContractTest`: the fixed message, the request-log test, and the `@AfterAll` every-pair assertion listing `GET /api/model-applications/{id} 404 not_found`. The WP02.2 security tests also failed.
   - `contract-coverage` then refused the failing report: `coverage.inputs` failed, and MockMvc evidence dropped from 28 pairs to 0.

### Defects found by the new checks and fixed

- **Next.js outcomes.** The BFF logged outcome `unlisted` instead of the contract code when it passed through or mapped a Spring error, or returned 503 `api_unreachable`. The health route did the same for its 503. `sessionRead` and the health route now record the outcome. A unit test covers both, and an SQL-like code from Spring is logged only as `unlisted`.
- **Next dev request logging.** Next dev printed raw request URLs, including callback `code` and `state`, to `web.log`. It is now disabled (`incomingRequests: false`).
- **WP03.2 record fields.** The record-field table in `WP03.2_BFF.md` listed `organisationCode`, `organisationName` and `modelName`. The record and schema fields are `organisation`, `brandName`, `category` and `modelNumber`; the table is corrected.

## 7. Limits

- Keycloak does not receive or record the correlation ID. The portal's `identity` lines are the only link between a browser request and a Keycloak call, and Keycloak's own event log was not inspected.
- Only `/api` route handlers are logged in Next.js. Page requests, static assets and middleware are not.
- Retention is enforced by the writers on a single workstation. There is no shipping, central store, tamper evidence or alerting.
- Some evidence is not from the shared runtime. The 11 stand-in-only and 3 unit-only browser pairs, and the 7 MockMvc-only Spring pairs, are labelled as such above.
- The stand-in answers only with documented codes and fixed messages, plus the planted values listed in the checks. It is not a fuzzing campaign.
- Schema validation uses the keyword subset that the artifact uses. Unknown keywords fail rather than being skipped, but this is not a full OpenAPI/JSON Schema implementation. No code generator was added.
- Correlation was shown for the read operations that exist. No write path exists to trace.
