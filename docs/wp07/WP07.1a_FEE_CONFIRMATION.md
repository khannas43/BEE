## What it does

`POST /api/model-applications/{id}/fee-confirmation` (browser route `/api/runtime/model-applications/{id}/fee-confirmation`) moves a submitted application from `fee_due` to `iame_scrutiny` when Finance confirms, by hand, that the fee on its snapshot was received. The screen is `/app/finance/finance-queue`, in the sidebar for a Finance identity only.

| Rule | Behaviour |
| --- | --- |
| Who | The reviewed slice rule `SliceAction.CONFIRM_FEE` through `SlicePolicy.check`: a Finance role with scope `all`, the `fee_due` source state, and nobody who already acted at another stage. A caller without a read scope, or with another role, gets 403 `role_not_permitted`. |
| Payer separation | A caller who belongs to the application's own organisation gets 403 `segregation_refused`. So does anyone who submitted it or took an earlier step. |
| What Finance sees | Only `fee_due` applications (the existing read scope). Any other application is the same 404 `not_found` as an unknown one. |
| Input | `version`, `receiptReference` (1 to 64 safe characters), `receivedOn` (not after today, India date), `amountInr` (decimal text). The amount must equal the fee snapshot exactly, else 422 `amount_mismatch`. |
| Atomic write | One transaction: the guarded state change (`fee_due` and the expected version), an append-only `model_application_transition_event`, an append-only `model_application_fee_confirmation`, and the assignment of the next IAME officer. |
| Next officer (provisional D2) | The active IAME account with the fewest open `iame_scrutiny` assignments, ties by id. If none is available, 409 `assignee_unavailable` and nothing is written. |
| Idempotency | A key is required. A repeat with the same body returns the stored **receipt** (header `Idempotency-Replayed: true`); a different body under the same key is 409 `idempotency_key_conflict`. The answer is a receipt, not an application view, so a replay never returns a record Finance can no longer read. |

## What changed

- **Flyway V25:** the two append-only tables (triggers and least-privilege grants: the runtime role can INSERT and SELECT only) and the disposable-cleanup function extended to remove the new rows and the assignments of throwaway applications.
- **Spring:** `gov.bee.api.finance` (controller, service, repository), generated by the scaffolder and then implemented; four new error codes with fixed messages.
- **Contract 0.7.0:** the operation on both layers, `FeeConfirmationRequest` and `FeeConfirmationReceipt`, the codes, and the per-feature BFF contract module `lib/server/contracts/fee-confirmation.ts`.
- **Screen:** `FinanceQueue` on the kit (`useRuntimeRead`, `ReadPanel`, `useCommand`, `CommandPanel`), a runtime route, and a shared `IdentityStrip`. `useRevalidation` gained `refresh()`.
- **Tooling (found and fixed on first real use of the scaffolder):** the request-log schema edit no longer breaks on a second feature; the contract-check inventory derives the expected Spring mappings and security allowlist from the contract instead of a hand-kept snapshot; the scaffolder tests use a sample name that is not a real feature.
