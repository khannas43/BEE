# WP05.1c — Submit draft → fee_due (S1 / A1)

**Status:** implemented locally; review corrections required before WP05.1c acceptance. WP05.1 and WP05 remain open; overall count 1/11.

## Scope

- `GET` / `POST /api/model-applications/{id}/submit` (Spring) and `/api/runtime/model-applications/{id}/submit` (BFF).
- Filing manufacturer or authorised agency on **own** draft only; brand/agency recheck from Spring DB at submit time.
- Category, performance-test standard and `new_model` fee rule must exist for submission date; missing rule → `422 rule_not_available` (fail closed).
- Fee snapshot at submit: amount, currency, rule key/version, verification, provenance; ₹24,000 RAC seed labelled **local demo** (`localDemoFee`, `label`), not BEE-approved.
- Atomic `draft` → `fee_due`, version increment, one submission event + one fee row per application; idempotent POST replay.
- UI: review/confirm provisional fee on the real draft screen; dashboard refresh via Spring list/read after submit.

## Review of `45db566` (2 October 2026)

The implementation reports `local:model-submit` 28/28 twice, the throwaway-schema submit tests, `api:test`, typecheck and build. These were not repeated in this review. Independent `web:test` (62/62), matrix (24/24) and access audit (9/9) passed. Five corrections are required before local acceptance:

1. **Append-only event and fee claim.** V9 permits UPDATE and DELETE on both submission tables; the live check deletes their rows. One row per application is enforced, but immutability is not. Add a later migration (do not edit applied V9) that prevents runtime modification/deletion and a test proving that guard. Preserve repeatable test cleanup through a controlled test-only mechanism or isolated schema.
2. **Replay scope.** `replayOrRequireKey` checks `canWrite` but does not recheck that the caller still belongs to the submitted application's filing organisation. A user moved to a different active organisation can replay their old key and receive the stored response. Fix submit and the shared WP05.1b create/PATCH replay path; test membership reassignment using disposable identities. Out-of-scope must not disclose the old record.
3. **Fee confirmation drift.** POST sends only the application version; fee rules are resolved again. A rule superseded between preview and POST can change the amount without the applicant confirming it. Bind the accepted fee rule/version and amount to the request and reject a changed preview with a safe conflict and no transition.
4. **Unsaved edit submission.** The edit form permits Submit while model/brand fields differ from the persisted draft. The confirmation shows only the fee and can submit the old version's data. Require saving changes first or display and confirm the exact persisted model/brand values; test the dirty-form case.
5. **Fee after refresh.** The submit response includes `submissionFee`, but ordinary GET detail and the dashboard use `ModelApplicationDraftService.view` and omit it. Make the stored fee snapshot visible to the authorised applicant on read after reload, using the strict BFF contract; keep Finance confirmation deferred to WP07.1.

WP05.1c, WP05.1 and WP05 remain unaccepted; accepted work packages stay 1/11.
