# WP07.1k — Real application review, workflow history and escalation views (Wave 1)

**Status:** Implemented locally on branch `wp07.1k-workflow-views`; the full local gate passes (see Evidence). **Not independently reviewed or accepted.** WP05.2 and the first slice remain open; the work-package count stays 1/11.

**Provisional local rules, not BEE rules.** Frontend only: no backend or contract change. All three screens read the same scoped application list as the stage screens, so Spring still decides what each person sees.

## What each screen does

| Route | Now |
| --- | --- |
| `/app/workflow/application-review` | Applications in progress that the person may see (not drafts, approved or rejected): reference, brand and model, organisation, stage, **the person's own next action** (a link to the screen where they can act, or "None for you") and a link to the history. |
| `/app/workflow/workflow-history` | The person's visible applications; choosing one shows its history (the WP07.1i read, so officers see notes and names, the applicant sees the withheld view). |
| `/app/workflow/escalation-dashboard` | A count of applications waiting at each stage. **No time limits exist**, so it never calls anything late, and says so on the screen. |

`/app/workflow/team-queue` is unchanged (still prototype data): a real team queue needs a read scope that is a security decision. Both gaps are in BL-128 and BL-129.
