# S3: simulated Fabric certificate ledger (demonstration)

- **Simulated.** "Simulated Fabric test network, not Hyperledger Fabric": real PostgreSQL tables (`ledger_tx`, `ledger_event`, V56 to V58), a pending/committed/failed state machine, and a per-certificate sha256 hash chain (hash = sha256(prev_hash | canonical certificate fields | kind | seq); first prev_hash is 64 zeros); every transaction carries a global block number. No network, no consensus, no chaincode.
- **Real.** Role and organisation scope in Spring (`gov.bee.api.demo.ledger.LedgerModule`, `/api/demo/ledger`), segregation (the submitter cannot commit or fail: `segregation_refused`, delegation counted), audit rows in the same transaction, append-only rows (the runtime login can only read; writes go through `ledger_*` functions).
- **Certificates untouched.** `certificate`, `issue_certificate()`, `public_certificate` and their tests are unchanged. A certificate with no ledger transaction is `not_submitted`. `certificate_id` has no foreign key so the maintenance cleanup of disposable applications is not blocked.
- **Status.** not_submitted | pending | active | failed | revoked | amended (a pending amend or revoke shows as "pendingKind" and does not change the status until committed). Amend changes only valid-to (ledger value; the certificate row stays).
- **Public verifier: decision, left unchanged.** `GET /api/public/verification` keeps its documented enum (valid, expired, not_yet_valid); extending it touches the OpenAPI artifact, contract pin, client, page and tests. The ledger status shows only on the internal screen. The integrator or S2 may add it later (a revoked certificate still answers "valid" publicly until then; say so in the demo or skip the public check for the revoked one).
- **Routes.** GET `ledger`, `ledger/transactions`, `ledger/{id}`, `ledger/{id}/verify`; POST `ledger/{id}/submit|commit|fail|retry|amend|revoke` (fail, amend, revoke need `reason`; amend needs `validTo`). Writers: programme, secretary, admin. Readers: also auditor; manufacturer sees its own organisation read-only.
- **Seed.** `local/seed/demo/s3_ledger.sql` takes the first four certificates (by issue time): active, pending, failed (attempt 2 failed, attempt 1 kept), and a **seeded mismatch** (tampered hash, labelled). Run after the demo frame has issued certificates.
- **Demo.** bee.secretary opens Ledger, picks the pending certificate: Commit is disabled (own submission). bee.admin commits it; Verify shows MATCH. Admin submits another, fails it with a reason, secretary retries (attempt 2), admin commits. Secretary amends valid-to, admin commits; admin revokes, secretary commits. Open the seeded-mismatch certificate: MISMATCH at transaction 1.
