# S1: payment simulation (local demonstration, provisional rules, not BEE rules)

- **Real:** Spring module `payments` (`gov.bee.api.demo.payments`) behind `/api/demo/payments`; tables `payment`, `payment_callback`, `payment_event` (append-only audit), `payment_receipt_counter` (V52-V53); role and own-organisation checks; amount fixed from the submit-time fee snapshot (fee + tax); callback de-duplicated by SHA-256 of the canonical payload (unique), second identical callback returns the first result with `replayed: true` and writes nothing; a different payload for a settled payment is `version_conflict`.
- **Simulated:** the gateway itself (the screen's "Pay now / Decline" panel is the callback sender), the gateway reference `SIMGW-xxxxxxxx`, the receipt `SIMRCPT-yyyymmdd-nnnn`. No money moves.
- **Unchanged:** the application state. Finance still confirms the fee in the Finance queue (payer cannot confirm own fee); the payment row shows the gateway reference to type as the receipt reference.
- **Routes:** POST `payments` {applicationId}; POST `payments/{id}/callback` {gatewayRef, outcome paid|failed, nonce}; GET `payments`; GET `payments/reconciliation` (Finance, admin, auditor).
- **Seed:** `local/seed/demo/s1_payments.sql` (5 fee-due applications DEMO-PAY-0001..5; payments paid, initiated, paid, failed; 0001 has none).
- **Demo:** nova.applicant opens Payments, pays DEMO-PAY-0001 at the simulated gateway, clicks Pay now, then Replay last callback (ignored), opens the receipt. bee.finance opens Payments: table with gateway reference, reconciliation shows paid versus confirmed and the paid-not-yet-confirmed difference; then confirms in the Finance queue with that reference. pixel.applicant cannot see or settle NOVA's payments.
