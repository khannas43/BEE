# WP05.1a — Model application read-only UI

Status: **local activity implemented; not accepted.** WP05.1 and the WP05 package remain open. Work-package count stays **1/11**. Branch `wp05.1-read-ui`, from `15e1246`.

This increment wires the existing authenticated BFF reads into one manufacturer/agency screen. Spring alone decides organisation, role, assignment and stage scope. The browser never filters by organisation or role, never sends a bearer token, and never treats the development preview role as authority.

**What this is and is not.** Partners already allowed to open `/app/model-label/model-dashboard` can list and open detail for model applications the BFF returns. Detail is a contextual panel on the same route (`?id=`), loaded with a separate GET. No create, edit, submit, fee, rating or approval control is offered as operational. `/app/registrations/record` is not opened to Manufacturer. Route policy and the screen matrix are unchanged; none of the 540 proposals is a grant. Writes, history, masters consumption and the rest of WP05.1 remain deferred.

## Routes and data

| Browser | Source | Notes |
| --- | --- | --- |
| Menu **My model applications** → `/app/model-label/model-dashboard` | Existing preview route for manufacturer and agency | Relabelled from "Approved models" because drafts and pending states appear in the persisted list |
| GET `/api/runtime/me` | Existing BFF (WP03.1) | Identity strip shows Spring `displayName`, roles and organisations — not the preview role |
| GET `/api/runtime/model-applications` | Existing BFF (WP03.2) | List body only; query parameters are not used to widen scope |
| GET `/api/runtime/model-applications/{id}` | Existing BFF (WP03.2) | Detail panel; out-of-scope, unknown and malformed IDs share one `404 not_found` |

Displayed fields are only those on `ModelApplication`: `reference`, `organisation`, `brandName`, `modelNumber`, `category`, `state`, `version`, `readBasis`, `id`. Lifecycle `localStorage` and prototype fixtures are not used for this list/detail slice. Other prototype screens and the development preview banner stay as they are.

## UI states

| State | Behaviour |
| --- | --- |
| Loading | "Loading model applications…" / "Loading application…" |
| Empty list | "No model applications are available to you." |
| Session missing / expired / unauthenticated | Fixed BFF message; sign-in link; no record data |
| 403 (`no_read_scope`, MFA/account/role denials) | Fixed BFF message |
| Detail 404 | "No such record is available to you." — same copy whether the id is unknown or another organisation's |
| Selected row | `?id=<uuid>` opens the detail panel; Close clears the query |

## Evidence (automated, mocked BFF)

`npm run web:test` includes `scripts/local/read-ui.test.mjs`. Responses are mocked at the BFF boundary. Spring authorization is **not** reimplemented as a client-side rule; the mock returns whatever Spring would have decided for that session cookie, and ignores `Authorization`.

| Check | Shows |
| --- | --- |
| Nova list | Three rows: LOCAL-MA-0001, 0002, 0004 (draft / fee_due / bee_scrutiny) |
| PixelCert list | One row: LOCAL-MA-0003 |
| Select record | Detail GET for the selected id returns that application's server fields |
| Cross-org / unknown id | Identical `not_found` failure; message does not say which case |
| No cookie | `no_session` on list and detail |
| Expiry | `session_expired` on list and detail |
| Bearer without cookie | Still `no_session` |
| Cookie + foreign bearer | Cookie persona's list only; cross-org detail still `not_found` |
| 403 | `no_read_scope` surfaced as forbidden |
| Empty list | Distinct empty state |
| Request shape | `credentials: "include"`, `cache: "no-store"`, Authorization stripped by `runtimeReadInit` |
