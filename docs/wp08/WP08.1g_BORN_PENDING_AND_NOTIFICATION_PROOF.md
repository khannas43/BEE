# WP08.1g — Proposals are born pending (BL-151) and the returned and rejected notifications proven live (BL-150)

**Status:** Implemented locally on branch `wp08-proposal-guards`; the full local gate passes (see Evidence). **Not independently reviewed or accepted.**

**Provisional local rules, not BEE rules.** Two small closures of backlog rows. No contract change.

## BL-151: a proposal cannot be inserted already decided

The runtime login may INSERT into the fee-rule, rating-scheme and fee-correction proposal tables (it records the proposal), and nothing forced a new row to be pending. A row inserted already approved, or decided by someone, would have skipped the second person. The fee-reversal table has had a guard since V40; **V41** adds the same one to the three older tables, as a single generic trigger function (`proposal_born_pending`) that refuses a row whose state is not pending or that carries a decision, a decision time or note, or an applied version or scheme. Only the decision functions move a proposal on, and they UPDATE, so no existing code path changes. The guard holds for every login, not only the runtime one.

Tests: one database test per table (`FeeRuleDatabaseTest`, `RatingSchemeDatabaseTest`, `FeeCorrectionDatabaseTest`) that tries a pre-rejected row and a pre-approved one through the runtime login and the owner, and finds nothing written. Migration count 41 in every database test.

## BL-150: returned and rejected notifications, live

The notification texts for a return and a rejection were proven in database tests only. The live checks now read the applicant's notification through the portal and compare it exactly:

- `local:return-resubmit` (now 109 checks): after the officer returns the application, the applicant's list holds an unread `returned` notification whose text is `<reference> (Nova Cool <model>) was returned to you: <reason> Edit it and send it again.`, and the text names no officer or role.
- `local:reject` (now 73 checks): after the rejection, an unread `rejected` notification reads `<reference> (Nova Cool <model>) was rejected: <reason>`.

Each read is also checked against the notification contract.
